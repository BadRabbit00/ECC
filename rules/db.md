# Data access

## Scope

Code that reads or writes PostgreSQL, MongoDB or Redis, plus migrations. The db-reviewer checks all of this in depth; this rule is what every writer must know.

## Rules

- R-DB-ORM-ONLY: query through the ORM/ODM: SQLAlchemy 2.0 (`select()`, `Mapped[...]`), GORM, Diesel/SQLx query builders, Beanie / typed `mongo-driver`. Raw SQL is an exception for analytics, `COPY`, `LISTEN/NOTIFY`, recursive CTEs, or a measured performance problem. It lives only in the repository, is parameterized, and carries a `# why not ORM:` comment.
- R-DB-NO-STRING-SQL: never build SQL with f-strings, `%`, `.format()`, `+`, or `fmt.Sprintf`, not even from "safe" values. A sort field comes from a whitelist.
- R-DB-PAGINATE-IN-QUERY: `LIMIT` (and keyset `WHERE id > :after` or `OFFSET`) belongs in the query. Never load rows and slice them in code. Count with `count()` in SQL.
- R-DB-SELECT-WHAT-YOU-NEED: load only the columns and relations you use (`load_only`, `selectinload`, projections). No `SELECT *` into memory to read one field.
- R-DB-NO-N-PLUS-1: never query inside a loop over query results. Use `selectinload` / `joinedload` / `WHERE id IN (...)` / GORM `Preload`.
- R-DB-TX-IN-SERVICE: the service owns the transaction; repositories call `add`/`flush`, never `commit`. Never make HTTP calls or send email inside an open transaction; do it after the commit or through the outbox.
- R-DB-RACES: "read → check → write" is a race. Use `with_for_update()` or a conditional `update(...).where(...).returning(...)`.
- R-DB-MIGRATIONS: the schema changes only through migrations (Alembic / goose / golang-migrate / sqlx / diesel). No `create_all()`, `AutoMigrate`, or DDL at startup. One logical change per migration; read the autogenerated file before keeping it; expand before contract.
- R-DB-INDEX-WITH-QUERY: a new filter or sort on a large table ships with an index in the same task. For composite indexes: equality columns, then sort, then range.
- R-DB-REDIS-DERIVED: Redis holds derived or temporary data only, every key has a TTL, and all Redis access lives in one module.
- R-DB-MONGO: the shape is a model with `schema_version`; no unbounded arrays inside a document; no manual "joins" in loops.

## Examples

### R-DB-PAGINATE-IN-QUERY — page in SQL

Bad:
```python
async def list_orders(self, page: int, size: int) -> list[Order]:
    rows = (await self.session.scalars(select(Order))).all()   # whole table
    return rows[(page - 1) * size : page * size]
```
Why: every page request loads the whole table into the process. It gets slower and heavier every day.

Good:
```python
async def list_orders(self, after: UUID | None, limit: int) -> list[Order]:
    stmt = select(Order).order_by(Order.id).limit(limit)
    if after is not None:
        stmt = stmt.where(Order.id > after)
    return list((await self.session.scalars(stmt)).all())
```

### R-DB-NO-N-PLUS-1 — load relations in one go

Bad:
```go
var orders []Order
db.Where("user_id = ?", uid).Find(&orders)
for i := range orders {
    db.Where("order_id = ?", orders[i].ID).Find(&orders[i].Items)   // one query per order
}
```
Why: 100 orders mean 101 queries. Latency grows with the data.

Good:
```go
var orders []Order
db.Preload("Items").Where("user_id = ?", uid).Order("created_at DESC").Limit(limit).Find(&orders)
```

### R-DB-NO-STRING-SQL — no string-built SQL

Bad:
```python
await session.execute(text(f"SELECT * FROM orders WHERE status = '{status}' ORDER BY {sort}"))
```
Why: SQL injection through both `status` and `sort`; typos in columns surface only at runtime.

Good:
```python
SORTABLE = {"created_at": Order.created_at, "total": Order.total_minor}
stmt = select(Order).where(Order.status == status).order_by(SORTABLE.get(sort, Order.created_at).desc())
```

### R-DB-RACES — atomic state change

Bad:
```python
order = await repo.get(order_id)
if order.status == OrderStatus.NEW:      # two requests both see NEW
    order.status = OrderStatus.PAID
    await session.commit()
```
Why: two concurrent payments both pass the check; the order is paid twice.

Good:
```python
paid = await session.scalar(
    update(Order)
    .where(Order.id == order_id, Order.status == OrderStatus.NEW)
    .values(status=OrderStatus.PAID)
    .returning(Order.id)
)
if paid is None:
    raise OrderNotPayable(order_id)
await session.commit()
```
